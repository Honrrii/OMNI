# OMNI-FRONTIER-0001 — Hypothesis

The Frontier Research orchestrator's `conclusion_state` for a research thread (CONFIRMED/REFUTED/SUPPORTED/etc.) is determined solely from a regex match against Claude's own free-text CONCLUDE-stage message, while Codex's independent EXPERIMENT_REVIEW-stage `REVIEW_FINDING` — the one place the protocol's "another agent's verdict is not evidence" / no-self-certification principle is supposed to bite for research conclusions — is recorded into the thread and archive but never read, compared, or allowed to veto/alter that conclusion_state. `ensure_multi_agent_participation` only checks that Codex *spoke somewhere* on the thread, not that its review content agrees with, or was incorporated into, the recorded verdict. This means a thread can reach a "dual-agent-verified" CONFIRMED/SUPPORTED conclusion even if Codex's real, independently-generated review explicitly disagreed with it — and nothing in the current code path would notice or stop that.

## Mechanism

`omni/frontier/orchestrator.py`'s `_record_conclusion` (line 530) calls `_extract_conclusion_state(message)` (line 98), which only regex-searches the CONCLUDE-stage `FrontierMessage.claim` — and that stage is only ever run by `self.claude` (`run_mock_shift`, line 656-657; STAGE_CONCLUDE never runs on `self.codex`). Codex's prior EXPERIMENT_REVIEW turn produces a `REVIEW_FINDING` message that gets appended to `thread_messages`/`messages.jsonl` for provenance, but `_record_experiment_review` (line 527-528) is a documented no-op ("procedural only in Phase 2B") — its content is never parsed, diffed against Claude's eventual verdict, or fed into `finalize_experiment_conclusion`. The only cross-agent guard, `ensure_multi_agent_participation` (line 189), checks `from_agent` set membership only — Codex having sent *any* message on the thread satisfies it, regardless of what that message said. In the current mock system this gap is invisible because `MockClaudeAdapter`'s CONCLUDE text and `MockCodexAdapter`'s EXPERIMENT_REVIEW text are both hardcoded to agree on "PROMISING_UNPROVEN" (agents.py:318-324 vs 430-436) — they agree because they share a scripted assumption, not because anything checks agreement. The uncommitted `run-dual-live-shift` work on this branch (scripts/omni_frontier_lab.py, tests/test_frontier_dual_live_wiring.py) is the first place two *independently real* models could occupy these two roles simultaneously, which is exactly when a genuine disagreement becomes possible for the first time — and the code path that would need to notice it does not exist.

## Competing hypotheses

- The primary failure mode may not be that Codex's EXPERIMENT_REVIEW verdict was accidentally omitted from a supposed veto path. A stronger competing explanation is that the current Frontier Lab protocol has no structured concept of multi-agent epistemic agreement at all: `REVIEW_FINDING` is intentionally procedural, while `conclusion_state` is a single-author, prose-derived field produced from Claude's final CONCLUSION message. Under this counter-hypothesis, a disagreeing Codex review is only one symptom. The same mechanism can misrecord a conclusion even without cross-agent disagreement, for example when Claude's prose negates or contrasts conclusion-state words.
