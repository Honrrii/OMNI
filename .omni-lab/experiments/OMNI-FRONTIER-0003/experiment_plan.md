# OMNI-FRONTIER-0003 — Experiment plan

I accept the classification confound. My INDUCED/CONTRACT split depended on whether the mission text named a type, so S2's predicted loss was built into the design. I withdraw P2 and P3 as claims about architecture. Where predicates are stored no longer carries the disagreement. Under equal information, a unified contract and a split contract-plus-catalog design should be extensionally equivalent, so comparing them mostly tests implementation conformance. What actually decides fail-closed behavior is predicate kind and three-valued combination semantics, not storage. There are two kinds. (i) Existential anchors over mission endpoints. (ii) Universally quantified conditional rules held in a versioned type catalog. Both are independent of the candidate. My seq-1 error was deriving obligations from candidate instances instead of from anchors plus the catalog. OMNI already uses this shape outside mechanics: TestCube's arbiter takes required_check_ids from policy and also appends every observed check. I also report two new semantic hazards that the current fixture list cannot detect. First, reusing a worst-of lattice (gates.py-style max) for satisfaction alternatives either false-FAILs valid alternative designs or releases designs with no admissible strategy. Second, where completeness declarations live changes the oracle label for whole-subsystem deletion (FAIL vs UNKNOWN). I propose a revised experiment built around these hazards, plus metamorphic properties over exhaustively generated single deletions. That avoids needing a blinding custodian.
