# Codex / Claude Handoff Packet

A handoff packet is a small Markdown block that gives Codex or Claude exactly the
context needed for one scoped OMNI engineering task — branch, scope, forbidden
areas, the commands to run, and a "do not commit until" checklist — without
pasting large amounts of repo history every time.

It is generated by `scripts/omni_handoff_packet.py` and pasted straight into the
chat. The tool is local-first and dependency-free: standard library only, no LLM
calls, no GitHub API, no network. It works offline and degrades gracefully
outside a git repository.

## When to use it

Use it at the start of a scoped task (an audit, a small feature, a stabilization)
when you want the assistant to stay inside guardrails and report back in a
predictable shape. It is not a project tracker and not an agent framework — it
generates one packet per task.

## Generating a packet

```bash
python scripts/omni_handoff_packet.py \
  --task "Phase 11 Stage 9B3D3 process-count feasibility audit" \
  --branch "omni/phase11-stage9b3d3-process-count-feasibility-audit" \
  --scope "Audit process_count enforcement feasibility; do not implement RLIMIT_NPROC yet" \
  --output /tmp/omni_handoff.md
```

Then paste the contents of `/tmp/omni_handoff.md` into Codex or Claude.

Omit `--output` to print to stdout instead of writing a file. Omit `--branch` to
use the current git branch.

## Options

| Flag | Meaning |
| --- | --- |
| `--task` | Task title (required). |
| `--branch` | Working branch. Defaults to the current git branch. |
| `--scope` | One or two sentences describing what is in scope. |
| `--forbid AREA` | Forbidden area (repeatable). Overrides the default OMNI forbidden list. |
| `--file PATH` | Relevant file or glob likely to matter (repeatable). |
| `--first-command CMD` | Command to run before editing (repeatable). Overrides defaults. |
| `--test-command CMD` | Command to run after editing (repeatable). Overrides defaults. |
| `--checklist ITEM` | Do-not-commit-until checklist item (repeatable). Overrides defaults. |
| `--commits N` | How many recent commits to include (default 5). |
| `--concise` | Token-minimized mode: fewer commits, drop repo status and reporting boilerplate. |
| `--output PATH` | Write the packet to a file instead of stdout. |

The default forbidden list encodes OMNI's standing constraints: sandbox
implementation, UI/frontend, ML model code, ROS export, Visual Bay, and mission
graph. Pass `--forbid` to replace that list for a task with different guardrails.

## Token-minimized mode

`--concise` trims the packet for smaller context windows: it drops the repo
status block and the reporting-format section, and includes fewer recent
commits. Use it when the receiving assistant already knows the workflow and you
only need branch, scope, forbidden areas, and commands.

## Example packet

Generated with the process-count feasibility audit as the example task:

```markdown
# OMNI Handoff Packet — Phase 11 Stage 9B3D3 process-count feasibility audit

_Generated 2026-07-07 for Codex/Claude. Paste this whole block into the chat._

## Current branch

`omni/phase11-stage9b3d3-process-count-feasibility-audit`

## Recent merged checkpoint

`f084e32 Merge pull request #57 from Honrrii/omni/phase11-stage9b3d2-address-space-enforcement`

## Scope

Audit process_count enforcement feasibility; do not implement RLIMIT_NPROC yet.
process_count remains deferred/fail-closed.

## Non-goals / forbidden areas

Do not modify these unless they are only referenced in docs/examples:

- Sandbox implementation (backend/app/sandbox/**)
- UI / frontend
- ML model code
- ROS export
- Visual Bay
- Mission graph

## Relevant files

- backend/app/sandbox/resource_policy.py
- docs/devops/codex_claude_handoff.md

## First commands to run (before editing)

    git status --short --branch
    git log --oneline -5

## Test commands (after editing)

    PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest tests -q

## Do-not-commit-until checklist

- [ ] Diagnosis / design summary shown
- [ ] Proposed diff shown
- [ ] Test results shown
- [ ] `git diff --stat` shown
- [ ] `git status --short --branch` shown

## Reporting format for Codex/Claude

Reply with, in order:

1. Diagnosis / design summary
2. Proposed diff
3. Test results
4. `git diff --stat`
5. `git status --short --branch`
```

(The `## Repo status` and `## Recent commits` blocks are also included in the
real output; they are omitted here to keep the example short.)
